云沙箱启动并发速度测试——结果指标说明

一、支持的驱动

阿里云：driver=e2b
字节/火山：driver=volcengine_native

两种驱动共享相同的调度、统计和CSV字段。字节/火山原生驱动中的
first_command_latency 实际表示首次Ready，second_command_latency实际表示
第二次Ready确认，并不表示在沙箱中执行了两条命令。

二、时间点与累计延迟

阿里云：
T0 = 开始调用Sandbox.create()
T1 = Sandbox.create()返回Sandbox ID
T2 = 第一条命令执行完成
T3 = 第二条命令执行完成

字节/火山原生：
T0 = 开始调用CreateSandbox
T1 = CreateSandbox返回Sandbox ID
T2 = DescribeSandbox首次返回Ready
T3 = DescribeSandbox第二次确认Ready

api_latency_ms = T1 - T0
first_command_latency_ms = T2 - T0
second_command_latency_ms = T3 - T0

三项都从创建开始累计，正常成功样本应满足：
api_latency <= first_command_latency <= second_command_latency

三、统计值

min：有效样本中的最小延迟。
max：有效样本中的最大延迟。
mean：有效样本的算术平均延迟。
P50：50%的有效样本不超过该延迟。
P90：90%的有效样本不超过该延迟。
P95：95%的有效样本不超过该延迟。
P99：99%的有效样本不超过该延迟。

exclude_first_from_mean=true时，每个TPS档位的第一个沙箱不参与mean，但仍参与
min、max、P50、P90、P95、P99和成功率统计。所有延迟单位均为毫秒，结果不需要
再除以attempts或sandbox_count。

四、成功率

api_success_rate_pct：创建成功且取得Sandbox ID的比例。
ready_success_rate_pct：阿里云两条命令均成功，或火山原生连续两次查询均为Ready
的比例。
cleanup_success_rate_pct：已创建Sandbox成功清理的比例。

五、本地调度

schedule_delay_p95_ms：95%的任务相对计划发起时间的本地延误不超过该值。该指标
用于判断本地压测程序是否按照目标TPS发出请求，不是云端Sandbox创建耗时。

六、基本字段

provider：厂商标识，例如aliyun、vol。
product_name：结果中显示的产品名称。
driver：实际使用的SDK驱动。
storage：none为无挂载，oss为对象存储，file为文件存储。
target_rate_per_s：目标每秒启动次数。
sandbox_count：当前并发档位计划创建的沙箱数量。
attempts：计划并实际提交到线程池的任务数量。
configured_max_workers：配置的线程上限。
effective_max_workers：当前档位实际使用的线程上限。

七、结果文件

原始明细.csv：每个请求一行，适合排查单次调用。
汇总.csv/汇总.json：当前运行各档位统计结果。
失败日志.csv/失败日志.txt：失败阶段、错误类型和错误信息。
results/全局测试历史.csv：追加保存所有历史测试。
results/全局测试结果.csv：保存各厂商、档位的最新结果矩阵。

逐字段定义见指标说明.csv，完整运行流程见README.md。
